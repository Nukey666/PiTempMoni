# 树莓派温度 / 风扇监控

Windows 桌面程序：SSH 拉取树莓派的 **CPU 温度**、**风扇转速**、**风扇 PWM**，
两条曲线实时显示（温度、转速），PWM 以大号读数显示——原因见下。

界面是 pywebview 套的系统 WebView2 + ECharts。**本地运行，不监听任何端口。**

## 下载

不想装 Python 的话，去 [Releases](../../releases) 下载 `PiMonitor.exe`，双击即用。
单文件、免安装、离线可跑（只要网络能通到树莓派）。

> **第一次运行会弹「Windows 已保护你的电脑」。** 这个 exe 没有数字签名，那是
> Windows 对未签名程序的默认拦截，不是病毒。点 **更多信息 → 仍要运行** 即可。
> 部分杀毒软件也可能误报 PyInstaller 打包的程序。
>
> 只想从源码跑的话，见下面的「运行」。

## 文件

| 文件 | 说明 |
| --- | --- |
| `reader.py` | SSH 采集，可单独 import / 单独跑，不依赖界面 |
| `app.py` | 主程序：窗口 + 采集线程 + 前后端桥 |
| `index.html` | 前端，单文件 |
| `echarts.min.js` | ECharts 5（本地文件，不走 CDN，离线可用） |
| `run.bat` | 双击运行，用 `pythonw` 不留黑框 |
| `build.bat` | 一键打包，输出 `dist\PiMonitor.exe` |
| `check_ui.py` | 桥是否通、连接/断开/重连 |
| `check_data.py` | 真机采集 → 出图（需要下面三个环境变量） |
| `check_errors.py` | 密码错 / 主机不可达 / 采集中途断网，用假 SSH 服务端 |
| `check_layout.py` | 各窗口尺寸下不溢出、按钮不被挤出窗口 |

`check_ui.py` 和 `check_data.py` 连真机，靠环境变量取连接信息，**不写死在源码里**：

```bat
set PI_HOST=192.168.1.100
set PI_USER=pi
set PI_PASS=你的密码
```

没设的话 `check_ui.py` 会跳过需要真机的那几项（桥和空主机拦截仍然会跑），
`check_data.py` 直接退出并返回 **2**（是「跳过」，不是「失败」）。
`check_errors.py` 和 `check_layout.py` 用假 SSH 服务端 / 只看布局，**不需要树莓派**。

## 运行

```bat
pip install -r requirements.txt
run.bat
```

或者 `python app.py`（会多一个黑框，因为 `python.exe` 是控制台程序）。

填 IP / 端口 / 用户 / 密码 / 间隔，点「连接」。

`reader.py` 也能单独跑：

```bat
set PI_HOST=192.168.1.100
set PI_USER=pi
set PI_PASS=你的密码
python reader.py
```

## 打包

```bat
build.bat
```

产物 `dist\PiMonitor.exe`（17 MB，两版 Tkinter+matplotlib 是 43 MB）。
拷到任意 Windows 机器双击即可，**不需要 Python，也不需要联网**。

## 实现要点

- **不监听任何端口。** pywebview 默认会为本地页面起一个 HTTP 服务
  （`webview/__init__.py` 的 `http_server or has_local_urls`），进程就监听
  `127.0.0.1` 的随机端口——`http_server=False` 拦不住，因为判定条件是「或」。
  页面改成用 `html=` 内联传入（`_page_html()`），`original_url` 为 `None`，
  判定为非本地，服务根本不会起。代价是 ECharts 要内联进页面。

  > 试过 `file:///` 形式：`is_local_url()` 确实放行，但 WebView2 静默不加载，
  > 表现是白屏、且**控制台零报错**，很难查。已放弃。

- **窗口句柄必须存在私有属性上**（`self._win`）。pywebview 会枚举 `js_api`
  对象的成员来搭 JS 桥，一旦碰到 `webview.Window` 对象就顺着
  `window.native.<属性>.<属性>...` 无限递归（`AccessibilityObject.Bounds.Empty.Empty...`），
  结果是 `Main window failed to start`。开发时不一定发作，**打包后必炸**。

- **前后端通信**：JS 调 `pywebview.api.connect/disconnect`；Python 用
  `window.evaluate_js("window.onXxx && window.onXxx(...)")` 回调。`&&` 是必要的，
  页面里的回调函数可能还没定义。

- **采集线程**：`threading.Thread` + `_alive()` 双重判定（既看 `running`，
  也看 `reader` 身份），断网/重连时不会把状态写串。断开时每 50 ms 醒一次，
  能立刻停。

- **温度读不到会报错停机，不会静默卡死**。远程命令整体失败时（thermal zone
  路径变了、`awk` 不在、shell 没起来），`printf` 出来的是 `,,` 这么一行，
  解析结果和「这一轮恰好没读到」**一模一样**。连续 `MAX_TEMP_MISSES`（3）轮
  拿不到温度就报错停机，并把远程原样回了什么带进状态栏——靠的是
  `reader.py` 多回传的 `raw` 字段，否则只能报一句没法查的「读不到温度」。
  **温度和转速不一样**：转速可以为空（风扇没有反馈线是正常的），温度是必选项。

  > 这是从 v1 带过来的老坑，v1 那版只是把人晾在「等待采样」上，到了 v2 变成
  > 一直挂绿色的「采集中」、图永远空着——都是卡死而不是报错。`check_errors.py`
  > 的场景 D 专门盯着这个：假 SSH 服务端一直回 `,,`，必须报错停机。

- **两根 Y 轴**：温度在左（0~100 °C，每 10 一格），转速在右（0~10000 RPM）。
  **不放图例**——轴的刻度和轴名各自跟曲线同色（温度琥珀、转速青），已经能对上号；
  图例在窄窗口里必然和两侧轴名打架。

- **温度曲线是渐变色的**：0 °C 冰蓝 → 25 淡青 → 50 暖黄 → 75 橙 → 100 火红，
  按温度连续着色（ECharts `visualMap` 的 continuous）。85 °C 阈值用一条红色虚线
  标出，而不是把超标的曲线改成硬红——颜色已经交给渐变编码了，再叠一层固定色等于
  在渐变上切一刀。虚线管「在哪」，标签管「多少」。渐变的 min/max 跟温度轴对齐，
  否则同一个温度在刻度上和颜色上是两个位置。

  > **坑**：温度 series 里**不能**写 `lineStyle.color` / `itemStyle.color`，
  > 写了就会盖掉 visualMap 算出来的颜色。实测低温 5 °C 和高温 98 °C 画出来是
  > 同一支琥珀 `#ffb454`（7521 vs 7496 像素，两条曲线一模一样）。颜色全权交给
  > visualMap，series 只管 `width`。
  >
  > 渐变中间那一档没用 `#4ec9b0`——那是转速曲线的颜色，温度走到 25 °C 附近
  > 两线会撞成完全一样的颜色。

- **图上最多留 900 个采样点**（`MAX_POINTS`）。900 是默认间隔（2 s）下的 30 分钟。
  这个上限同时也是缩放旋钮：间隔调短就看得细、窗口自然变短（0.5 s → 7.5 分钟），
  间隔调长就拉得远（10 s → 2.5 小时）。**没有**按「固定 30 分钟窗口、点数随间隔
  浮动」来做——那样 0.5 s 间隔下要画 3600 个点，而温度在 0.5 秒尺度上基本不动，
  多出来的点全是冗余。`check_data.py` 灌 950 个样本验的是「丢掉最老的 50 个」，
  不只看个数——只数个数字的话，从头裁剪也会通过。

- **PWM 不进图，也没有专属坐标轴**。PWM 是**分档量**，不是连续量：设备树
  `cooling_fan/cooling-levels` 是 `[0, 75, 125, 175, 250]`，内核调速器只写这
  五档（详见「已知问题」）。给它配一根连续的 0~100% 轴、画一条线，等于拿无级
  尺子量五级台阶，反而让人以为它连续可变。而且 PWM 是「因」、转速是「果」，
  果已经在图上了——风扇什么时候升档，从转速曲线上看得出来。
  PWM 只剩大号读数：sysfs 的 `pwm1` 原始值是 0~255，界面换算成百分比并
  **归到十位**（`pwmPercent()`），五个档位正好落成 **0 / 30 / 50 / 70 / 100**
  ——一位十进数就是一级，不用再跟 29、49、69、98 这种不是整十的数较劲。

  > 曲线撤掉的另一个好处：右侧省下 62px 偏移 + 一格轴宽（`grid.right`
  > 从 148 降到 86），全给温度/转速两条曲线。

- **悬浮提示**带单位（`°C` / `RPM` / `%`），无数据的项显示 `—` 而不是断在半空。

- **读数区**：三个大号等宽数字，顶部一条与曲线同色的色条。状态栏只说状态，
  数值不重复占宽度；错误信息过长时截断，鼠标悬停可看全。

- **窗口窄时**控制栏折成两行，而不是把「断开」按钮顶出窗口外。主机名那一格
  会先收缩。实测最小尺寸下按钮始终可见。

## 已知问题

- 温度轴固定 0~100 °C、转速轴固定 0~10000 RPM，**不自动缩放**。
  转速上限 10000 的依据：官方 Pi 5 Active Cooler 标称 8000 RPM ±15%（上界 9200），
  **作者实际观测到最高约 9000 多**，取 10000 留一点余量，是合适的。

  > **9000 这个数是作者提供的，不是本程序实测的。** 程序在真机上只量到一个可信
  > 点：调速器第 1 档（PWM 75）稳态约 **2860 RPM**。更高档位对应
  > 60 / 67.5 / 75 °C，idle 下够不到；要量就得给 CPU 加负载或直接写 sysfs，
  > 两条都是改动机器，没做（见下）。
- **PWM 只有五档**。设备树 `cooling_fan/cooling-levels` 是 `[0, 75, 125, 175, 250]`
  （对应 `cooling_device0` 的 state 0~4），内核调速器**从来不写 255**，顶格 250
  ——也就是满量程的 98%。原始换算过来是 0 / 29 / 49 / 69 / 98，**归到十位**后显示
  **0 / 30 / 50 / 70 / 100**。这正是 PWM 不进图的理由，也是读数只在这五个值之间
  跳的原因——中间那些数永远不会出现，它们不代表任何真实档位。

  > 顶格 250 显示成 **100%** 是取整的结果，**不是**内核真的写满了 255。
  > 别把它当成「风扇已满转」的依据。

  顺带：风扇完全归内核热控管（50 °C 开、45 °C 关，迟滞 5 °C），`config.txt` 里
  没有任何风扇设置，程序也**只读不写**。
- **主机和用户名不预填**（规格原文写的是 `192.168.1.100` / `pi`）。预填一个不是
  用户自己的值，比留空更容易让人直接点「连接」连错地方。端口 22 / 间隔 2 保留默认
  ——它俩是协议和行为默认，跟"哪台机器"无关。空主机、空用户名有前置校验，
  会提示成「请先填写主机地址 / 用户名」，不会抛出 paramiko 那种看不懂的异常。
- 采集中途断网后只会停下并报错，不会自动重连，需要手动点「连接」。
